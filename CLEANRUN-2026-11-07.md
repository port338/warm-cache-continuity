## Findings

**F1 — Step 4 assumes `AGENTS.md` already exists.** On a brand-new workspace there is no
`AGENTS.md`, so "add step 3.5 between step 3 and step 4" has no anchor. The skill needs an
explicit instruction: create the file with a `## Session Startup` section first, or edit the
agent's template.

**F2 — Phase 4 scripts disagree about the workspace path.** `session-cache-chroma-meta.py`
honours `OPENCLAW_WORKSPACE`; `session-cache-backfill.py` and `session-cache-digest.py`
hardcode `~/.openclaw/workspace`. On a non-default workspace the digest silently reads the
wrong directory. Fixed in this package: all three now share the same resolution order
(`OPENCLAW_WORKSPACE` → `~/.openclaw/workspace`).

**F3 — Phase 4 does not say that the third script needs the `chromadb` package.** Running it
on a clean profile fails at import. Added a one-line requirement to the skill.

**F4 — the first `/new` writes a header-only file.** The check "a new file appears" passes
while the file contains only the session header, because there were no messages yet. This is
correct behaviour, but the skill should say so, otherwise it looks like a partial failure.

**Method note (not a skill defect).** A second Gateway started from a shell that inherits the
host service environment dies with `SIGTERM ... source=systemd user openclaw-gateway.service`
within about a minute. For an isolated run, start it with a clean environment:

```bash
nohup env -i HOME=/tmp/warmclean PATH="$PATH" TERM=dumb \
  openclaw gateway --port 19003 --auth token --token <test-token> --allow-unconfigured \
  > /tmp/warmclean-gw.log 2>&1 &
```

## Reproduce

```bash
mkdir -p /tmp/warmclean
export HOME=/tmp/warmclean
openclaw gateway --port 19003 --auth token --token <test-token> --allow-unconfigured &
cd "$HOME/.openclaw/workspace"
mkdir -p memory/session-cache
# write a cache file, then follow Step 4–6 and Phase 4 of SKILL.md
```

## Regression after the fixes

After F2 was fixed, the same profile was re-run:

| Check | Result |
|---|---|
| `python3 -m py_compile` on both scripts | OK |
| `session-cache-digest.py` with no environment variable | reads `~/.openclaw/workspace`, reports `3 файлов, актуальных 1, вне окна 2` |
| `OPENCLAW_WORKSPACE=<workspace> session-cache-digest.py --tasks` | returns the 2 active tasks, exit 0 |
| `OPENCLAW_WORKSPACE=/tmp/emptyws session-cache-digest.py` | `session-cache не найден: /tmp/emptyws/memory/session-cache`, exit 1 — fails loudly instead of reporting an empty cache |
| `session-cache-backfill.py` re-run | `размечено: 0, уже с frontmatter: 3, пустых: 0` — idempotent |

## Bottom line

The core mechanism is reproducible from zero: directory, cache file, hook enablement, the
hook actually firing on `/new`, and the digest with its TTL rules. Two areas remain
unverified on a clean profile — ChromaDB (external service) and the living loop (extra
plugin, automations, model provider). The three defects found are fixed in the same commit
that adds this report.

What is still not proved from zero: a real chat transport (Telegram/Matrix delivery),
